# ▰ Principios de arquitectura

## 01 — Enterprise First

La plataforma debe sentirse diseñada para empresas que operan sistemas críticos.

No se busca una experiencia de:

```text
"Agencia de marketing"
```

sino de:

```text
"Engineering Partner"
```

---

## 02 — Performance First

Toda sección debe considerar:

* Core Web Vitals
* carga progresiva
* imágenes optimizadas
* lazy loading
* reducción de JavaScript innecesario
* CSS eficiente
* reducción de dependencias
* SSR cuando aporte valor

---

## 03 — SEO + LLM Readability

El contenido importante debe existir en el **HTML inicial** siempre que sea posible.

Evitar depender exclusivamente de:

```text
JavaScript
    ↓
fetch()
    ↓
render()
    ↓
contenido visible
```

Preferir:

```text
Server / Static Content
        ↓
HTML
        ↓
Crawler / Google / LLM
        ↓
Hydration
        ↓
Interactividad
```

El objetivo es que buscadores y sistemas de IA puedan interpretar correctamente:

* servicios
* especialidades
* casos de uso
* tecnologías
* ubicación
* propuesta de valor
* información corporativa
* FAQs
* contenido editorial

# ◇ CSS Architecture

El proyecto utiliza Tailwind CSS v4 junto con CSS específico de la experiencia.

Existe una consideración importante:

```text
Tailwind @layer
       │
       │
       ▼
maquetado-dossier.css
       │
       ▼
Higher Cascade Priority
```

`maquetado-dossier.css` contiene estilos fuera de las capas de Tailwind y puede tener prioridad sobre determinadas reglas generadas por Tailwind.

Antes de modificar estilos globales, revisar:

```text
docs/
design/
src/maquetado-dossier.css
```
